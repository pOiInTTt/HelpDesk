# HelpDesk — система учёта заявок

Учебный проект: приём и обработка заявок в службу поддержки. Клиент создаёт заявку и смотрит её статус, сотрудник назначается исполнителем и меняет статус. Все изменения сохраняются в истории, к заявкам можно оставлять комментарии и прикреплять файлы.

## Возможности

- Создание заявки и получение заявки по номеру
- Список заявок с фильтрами, сортировкой и постраничной выдачей
- Назначение исполнителя и смена статуса (Новая → В работе → Закрыта)
- История изменений заявки (хранится в `history.json`)
- Комментарии: просмотр, добавление, изменение и удаление (только автором)
- Вложения: PDF, PNG, JPEG до 5 МБ, метаданные в SQL Server
- Проверка данных, понятные сообщения об ошибках, журнал ошибок в `logs/errors.log`
- Простой веб-интерфейс для клиента (HTML + JS)

## Технологии

- C#, .NET 9, ASP.NET Core Minimal API
- ADO.NET, Microsoft.Data.SqlClient
- Microsoft SQL Server
- Swagger (Swashbuckle)
- HTML и JavaScript (без фреймворков)

## Что нужно установить

1. [.NET SDK 9](https://dotnet.microsoft.com/download)
2. Microsoft SQL Server и SQL Server Management Studio (SSMS)
3. Visual Studio Code с расширением REST Client (для проверки запросов)

Проверка установки:

```
dotnet --version
```

## Структура проекта

```
HelpDesk/
├── Program.cs            основной файл: настройки и все эндпоинты
```

При работе создаются папки `uploads/` (загруженные файлы) и `logs/` (журнал ошибок). В git они не загружаются.

## Запуск

### 1. База данных

1. Откройте SSMS и подключитесь к серверу.
2. Из папки `database` откройте скрипт создания базы и выполните его (F5). Будут созданы база `HelpDesk`, таблицы и тестовые данные.
3. Выполните скрипт создания таблицы `RequestComments`.
4. Выполните скрипт создания таблицы `RequestAttachments`.

Выполняйте скрипты именно в этом порядке: таблицы комментариев и вложений ссылаются на таблицу `Requests`.

### 2. Строка подключения

В `Program.cs` найдите переменную `cs` и укажите имя своего сервера, например:

```csharp
var cs = "Server=localhost;Database=HelpDesk;Trusted_Connection=True;TrustServerCertificate=True;";
```

Имя сервера можно посмотреть в окне подключения SSMS.

### 3. Запуск сервера

В терминале, в папке проекта:

```
dotnet run
```

В консоли появится адрес вида `http://localhost:5032`. Порт у вас может отличаться, используйте тот, который показан в консоли.

Остановить сервер: `Ctrl + C`.

### 4. Что открыть

| Что | Адрес |
|---|---|
| Swagger (проверка API) | `http://localhost:5032/swagger` |
| Интерфейс клиента | `http://localhost:5032/` |

## API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/requests` | Список заявок (фильтры, сортировка, страницы) |
| POST | `/api/requests` | Создать заявку |
| GET | `/api/requests/{id}` | Заявка по номеру |
| PUT/PATCH | `/api/requests/{id}/assign` | Назначить исполнителя |
| PUT/PATCH | `/api/requests/{id}/status` | Изменить статус |
| GET | `/api/requests/{id}/history` | История изменений |
| GET | `/api/requests/{id}/comments` | Комментарии заявки |
| POST | `/api/requests/{id}/comments` | Добавить комментарий |
| PUT | `/api/requests/{id}/comments/{commentId}` | Изменить комментарий (автор) |
| DELETE | `/api/requests/{id}/comments/{commentId}` | Удалить комментарий (автор) |
| POST | `/api/requests/{id}/attachments` | Загрузить файл (PDF, PNG, JPEG, до 5 МБ) |

Точные адреса и параметры смотрите в Swagger.

### Параметры списка заявок

| Параметр | Значение |
|---|---|
| `status` | статус заявки (по умолчанию все) |
| `priorityId`, `categoryId`, `employeeId` | фильтры по приоритету, категории, исполнителю |
| `search` | поиск по тексту |
| `sort` | `id`, `createdAt`, `priority`, `status`, `title` |
| `order` | `asc` или `desc` (по умолчанию `desc`) |
| `page`, `pageSize` | страница (по умолчанию 1) и размер страницы (1–100, по умолчанию 10) |

Ответ: `{ total, page, pageSize, totalPages, items }`.

### Правила

- Статусы: «Новая» → «В работе» → «Закрыта». Возврат из «Закрыта» в «В работе» запрещён.
- Назначение исполнителя переводит заявку из «Новая» в «В работе».
- Для комментариев автор определяется по авторизованному пользователю. Для проверки без авторизации передавайте заголовок `X-Employee-Id: 1`. Это временное решение для тестов.

### Коды ответов

| Код | Значение |
|---|---|
| 200, 201, 204 | успех |
| 400 | некорректные данные |
| 401 | не определён пользователь |
| 403 | действие разрешено только автору |
| 404 | заявка, комментарий или исполнитель не найдены |
| 409 | недопустимый переход статуса |
| 413 | файл больше 5 МБ |
| 500, 503 | ошибка сервера или базы данных (подробности в `logs/errors.log`) |

## Проверка работы

1. Откройте `requests.http` в VS Code (расширение REST Client) и нажимайте «Send Request» над нужным запросом.
2. Результаты проверок и скриншоты лежат в папке `result`.
3. Для проверки вложений подготовьте тестовые файлы (PDF, PNG, JPEG, TXT и файл больше 5 МБ).

## Безопасность загрузки файлов

- Допускаются только PDF, PNG и JPEG; тип проверяется по расширению и по содержимому файла.
- Максимальный размер: 5 МБ.
- Файл сохраняется под случайным именем (GUID), исходное имя не используется как путь и хранится только в БД.
- Файлы лежат в отдельной папке `uploads`, которая не раздаётся как статика.
- Если запись в БД не удалась, сохранённый файл удаляется.
- Нельзя загрузить файл для несуществующей заявки.

## Частые проблемы

| Проблема | Что делать |
|---|---|
| Не подключается к БД | Проверьте имя сервера в `cs` и что SQL Server запущен |
| Ошибка «Invalid object name» | Не выполнен один из SQL-скриптов |
| Порт отличается от `5032` | Используйте адрес из консоли и поправьте `@host` в `requests.http` |
| Белая страница или ничего не происходит | Откройте консоль браузера (F12) и посмотрите ошибку |
| Файл не загружается | Проверьте тип файла (PDF, PNG, JPEG) и размер (до 5 МБ) |
